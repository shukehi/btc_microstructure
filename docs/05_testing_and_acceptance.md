# 05 · 测试与验收规范

版本：0.1｜以下均为待实现测试及其预期，不表示软件已通过测试。

## 1. 测试层级

单元测试使用人工固定数据；协议测试使用保存的真实响应样本；重放测试使用原始与控制日志；运行验收使用目标部署机器。测试中的合成市场价格与数量只用于验证计算。

实现必须提供测试证据文件：test_id、软件提交、配置、fixture 校验和、执行时刻、结果、失败原因。未执行记录为 NOT_RUN，不能写 PASS。

## 8. 成本测试

TEST-COST-01：cost enabled=true，费率或数量为空。预期：启动验证失败；不能按零费用默默运行。

TEST-COST-02：人工情景，做多 q=1 BTC，p_e=100，p_x=101，每边费率0.001，期间一次 mark=100、funding=0.0001。毛损益1，费用0.201，资金费用0.01，净损益0.789 USDT。此为公式测试，不是真实费率或交易建议。

额外覆盖做空资金收付符号、没有跨结算时不得扣资金费、恰在边界时标记不确定、滑点与价差不得双重扣除。

## 9. 持久化、重放与运维测试

| 编号 | 场景 | 预期 |
|---|---|---|
| TEST-STORE-01 | 标准化程序崩溃 | 原始已提交日志不变；可重算 |
| TEST-REPLAY-01 | 相同原始＋控制日志运行两次 | 行选择、标志、状态与值在容差内一致 |
| TEST-REPLAY-02 | 60秒检查点重放 vs 从原始同步重放 | 相同有效游标后的簿状态与特征一致 |
| TEST-OPS-01 | 检查所有网络调用 | 不包含下单、私有账户或签名调用 |
| TEST-OPS-02 | 模拟429、418、网络断开 | 限速退避／人工检查／登记缺口，非无限重试 |
| TEST-OPS-03 | 写盘失败、容量耗尽、队列溢出 | 显式错误和降级；无静默覆盖／虚假连续性 |

逻辑值的比较：ID、Decimal、数量定点、序号、布尔与质量必须完全相同。Float64 默认 rtol=1e−10、atol=1e−12，涉及 bps 大数和累计和时按特征规定单独给出容差，不以任意放大容差掩盖错误。

## 10. 验收门槛

### M0 协议验收

每个必需来源至少取得可解析样本，记录官方文档版本与实际响应。验证路由、订阅封装、字段类型、元数据、预算、时钟单位。没有数据不能用文档示例冒充现场样本。强平未发生可记录“连接核验，事件待观测”，但不能称其实际 payload 已验证。

### M1/M2 工程验收

全部适用固定测试通过。至少一次受控断线与恢复演练。指定参考硬件上连续24小时采集目标负载，记录真实覆盖率、峰值输入、内存、队列年龄和写盘延迟；这是待执行验收要求。

首版工程目标：有网络和存储条件下，核心流有效覆盖≥99%，1秒特征截止至发布延迟p99≤1000ms，队列不无界增长，未标记的已知缺口为零。覆盖率分母为计划运行时间；是否计入计划维护必须预先约定并同时报告原始口径。未达标可以修订资源或配置，但不能据此修改研究结果。

24小时稳定运行不等于积累了足够统计样本。长周期研究需另满足研究划分、独立事件和市场区间要求。

### M3/M4 研究验收

泄漏和标签测试全部通过，所有候选期限均报告，结果可重现。成本依赖齐全才能验收净成本模块。工程验收不要求盈利，亦不允许用盈利掩盖数据错误。
