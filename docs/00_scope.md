# 00 · 项目范围与需求规格

版本：0.1｜状态：开发规格初稿｜基准日期：2026-10-10

## 1. 项目目的

建设一个可在个人计算机运行的 BTC 永续微观结构研究系统。系统采集和保存行情事件，将其转为可解释的特征，并检验这些特征与不同期限后价格变化的关系。研究结果必须能够追溯到输入数据、处理规则、配置和软件版本。

本项目首先解决数据与研究的可信性，不以产生更多交易信号作为验收标准。

## 3. 第一版范围

### 3.1 必需能力

采集永续及现货聚合成交、两市场最优报价、永续标准 L2 增量及初始化快照、永续当前 OI、标记/指数价格、资金费率观测与结算历史。强平快照作为补充数据接入，但不作为核心管线工作的前提。

保存原始消息与标准化表；维护有效性与来源；支持确定性重放；生成特征、描述性状态、多期限价格标签及研究报告。

第一版现货只要求最优报价，不要求完整现货 L2。现货报价缺少交易所时间戳时，只进入接收时间分析，不能凭空构造事件时间。

### 3.2 不在范围内

自动下单、API 私有账户读取、杠杆或仓位推荐、多账户管理、真实订单身份重建、完整交易所撮合引擎模拟、L3 队列位置识别、全市场强平总量估计、跨交易所全景价格发现、毫秒级竞速交易与网页仪表盘。

历史成交文件可导入，但不得承诺存在与其同期间、同精度的历史 L2、秒级 OI 或真实接收时间。缺什么就明确缺什么。

## 5. 非功能要求

**可重现。** 运行清单必须包含 schema_version、adapter_version、feature_version、配置摘要、代码提交、依赖锁文件摘要、输入文件校验和、时间视图、运行编号和随机种子。

**可观察。** 任何组件不得静默丢弃异常消息或伪造零值。严重问题允许停止派生输出，但仍应尽可能保留原始记录。

**精度。** 原始价格数量按字符串保留；标准化使用 Decimal128 或经元数据确认的定点整数；研究矩阵允许 Float64，并记录转换精度。禁止用二进制浮点价格作为订单簿唯一键。

**资源。** 第一版采用有界队列和分批写盘，不要求引入分布式消息系统。性能目标必须在记录硬件环境后实测；本文不宣称某台个人电脑必然能承受全部行情峰值。

**安全。** 仅访问获准使用的公开数据服务，遵守服务权限和限流。连接受限时报告原因，不设计绕过地域、账户或网络限制的路径。

## 6. 数据解释边界

OI 是未平仓合约总量，不直接提供交易双方的开平仓标记。[S11](08_sources_and_decisions.md#source-s11) 因而“价格涨且 OI 涨”只是一种观测组合；关于新增多仓主导或空头被套的解释必须标为假设。

标准 L2 的数量变化不是逐订单生命周期。不得将聚合档位缩小全部归为撤单，也不得声称识别出了交易者身份。CVD、盘口 OFI、OI 与资金费率职责分开，不能互换名称。

资金费率为正不等于做空信号；现货主动买盘不等于证明上涨质量更好；某状态的价格研究表现不等于可执行净收益。

## 7. 完成标准与里程碑

| 阶段 | 交付内容 | 通过条件 |
|---|---|---|
| M0 | 配置模型、资料登记、协议冒烟报告 | 必需端点与样本字段核验；不能把文档核验当连通测试 |
| M1 | 原始采集、标准化、质量记录、简单重放 | 去重、时间和持久化固定样例通过 |
| M2 | L2 状态机和第一批特征 | 序列断裂、预热、公式与重放一致性测试通过 |
| M3 | 状态、标签、多期限事件研究 | 因果时间约束和样本外划分测试通过 |
| M4 | 成本敏感性与模拟执行研究 | 参数齐备、计算独立验证；不以盈利作为工程验收条件 |

文档完成与软件完成是两件事。v0.1 文档允许保留附录中的外部核验项；进入某阶段前，必须关闭该阶段依赖的阻塞项。

## 8. 变更规则

改变成交口径、时间视图、OI 单位、订单簿来源、费率含义、窗口边界或收益起点，均必须增加相应版本。更改候选期限、过滤条件、特征选择或成本情景，必须创建新的 research_run_id。不得覆盖旧结果后继续沿用旧结论。
