# 06 · 配置、运行与运维合同

版本：0.1｜状态：程序实现应遵循的操作规范；本包没有可启动的采集器

## 1. 参考环境

Python 3.12 作为首版开发基线，实际依赖版本在实现时锁定。建议组件为 asyncio、aiohttp、PyArrow、Polars 或 pandas、NumPy、SciPy、pytest；分析可以增加 DuckDB。这里不宣称使用的是各库最新版本，也不固定未经兼容性测试的依赖组合。

参考验收环境可使用 Linux x86_64、4核、16GB内存、SSD；这是测试基线，不是根据真实峰值测出的最低硬件。用户实际系统和存储空间应在 M0 记录，不需要在文档编写前虚构。

## 2. 配置合同

配置样例见 `config/research.example.yaml`。所有时间长度以明确单位命名；价格与数量相关金额用字符串或整数避免 YAML 浮点误解。未知费率、订单数量和来源单位使用 null，不用0代表未知。

配置加载必须检查：未知键、非法枚举、重复窗口、非正期限、无效路径、成本依赖、时间视图与来源能力、档位范围与快照覆盖。配置摘要进入每个研究运行。

M0 生成的 endpoint_budget、instrument metadata、protocol_probe_report 与配置分开存储，并由 manifest 引用。关闭必需流需要显式标记降级运行，不允许在报告标题仍声称完整系统。

## 3. 运行入口应具备的子命令

以下是**待实现 CLI 合同**，不是当前可执行命令：

| 子命令 | 必须完成的工作 |
|---|---|
| validate-config | 本地解析和语义校验，不连接网络 |
| probe | 只读连接、元数据、订阅样本和预算检查 |
| collect | 启动原始日志与指定来源，不执行交易 |
| replay | 从输入manifest重放；不访问交易账户 |
| build-features | 按指定视图、版本和输入生成特征 |
| research | 根据特征manifest生成多期限研究 |
| health | 输出当前状态、依赖年龄和错误 |
| verify-storage | 检查校验和、记录游标与提交清单 |

程序尚未实现时，README 不得给出看似已经可运行的 `python -m ... collect` 成功承诺。

## 4. 启动与停止

启动依次验证配置、目录写权限、剩余空间、时钟健康、元数据、协议预算与必需流。原始写盘就绪后再宣布 RUNNING；L2 单独等待 LIVE。OI 与滚动特征尚未预热时正常显示 WARMUP。

停止先禁止新的研究任务，停止接收，排空有界写盘队列，提交文件和清单，保存有效检查点与停止标记。强制退出后下次启动只能恢复到可信提交点，并标记尾部不确定区间。

## 5. 健康指标

每个流独立输出 connection_state、last_message_receive、message_rate、known_gap_count、reconnect_count、parse_error_count。L2 增加 book_state、epoch、last_u、coverage_bps；OI 增加 poll_age 与 observation_age。

全局指标包括 ingest_queue_records/bytes/oldest_age、raw_commit_age、feature_publish_lag、clock_health、磁盘可用空间、已提交文件数量、schema冲突和失败任务数。

“连接在线”与“数据有效”分别展示。强平流没有新消息不能仅凭消息年龄告警；OI 相同结果不断返回也不意味着观测时间不断更新。

## 6. 告警与处置

| 问题 | 自动行为 | 人工检查 |
|---|---|---|
| 可恢复网络错误 | 退避重连、标记来源缺口 | 高频复发时检查网络和端点 |
| 盘口序列失效 | 禁止簿特征、重新同步 | 检查协议与处理积压 |
| 429 | 共享预算降速，遵守有效重试提示 | 检查其他进程是否共享IP预算 |
| 418/权限拒绝 | 停止自动压力重试 | 确认服务允许性和限制原因 |
| 新增未知可选字段 | 原始保留，记录schema观察 | 核验后更新适配器 |
| 必需字段类型改变 | 隔离该流派生处理 | 升级schema和测试 |
| 磁盘低空间 | 暂停非必需回填、告警 | 扩容或按已批准保留政策归档 |
| 严重时钟错误 | 标记受影响区间 | 恢复时间同步后新epoch／新运行 |

默认磁盘预警10GiB、停止门槛2GiB仅用于样例。必须结合磁盘大小和实际写入速率校准。不得自动删除未经校验备份的唯一原始数据。

## 7. 恢复步骤

校验最近 manifest；隔离未提交文件；确定最后可信输入游标；登记不确定缺口；必要时重新拉取可补回成交；L2 重新同步；重放派生数据；审查质量报告后恢复研究。

不要用新快照填补故障期间的历史盘口。不把补回后的完整研究视图覆盖原来的实际接收视图。

## 8. 运行清单

每次运行至少记录：run_id、spec_version、git_commit（尚未实现则明确未设置）、Python与依赖版本、配置hash、adapter版本、源资料核验日期、端点预算版本、机器规格、开始结束时间、时区、随机种子、输入输出manifest。

保存日志时排除密钥、认证头和个人账户信息。第一版不需要交易API密钥；若某扩展公开数据服务要求认证，必须另行审查权限范围，不能自动读取用户现有交易密钥。
